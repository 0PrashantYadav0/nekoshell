# iTerm2

## What it configures

`nekoshell terminal apply` writes one dynamic profile file, `~/Library/Application Support/iTerm2/DynamicProfiles/nekoshell.json`, generated by `terminals/iterm2/build-profiles.py` from `core/theme/palettes.json`. It holds two profiles. `nekoshell` is the main one: JetBrainsMono Nerd Font at 15 points (as the PostScript name `JetBrainsMonoNF-Regular`, which iTerm2 wants), the Catppuccin flavour in force as the sixteen ANSI colours, foreground, background, cursor and selection, and a status bar along the bottom with the working directory and git branch on the left and CPU, memory, battery and the clock on the right. The second profile is the music panel (see below). iTerm2 watches that directory and re-reads the file within seconds, so a theme switch shows without a restart.

The same apply downloads iTerm2's own zsh hooks to `~/.iterm2_shell_integration.zsh` when the file is not there yet; the core zshrc sources it inside iTerm2, and it is what feeds the status bar's directory and git components. A failed download only warns.

The global preferences are the other half: the default profile (`Default Bookmark Guid`), the hidden tab bar and scrollbar, 16 by 12 point margins, no prompt on quit, and dimmed inactive split panes. iTerm2 rewrites its preferences file from memory when it quits, so these are only written while iTerm2 is not running. An apply from inside iTerm2 warns and leaves them for later: quit iTerm2 and run `nekoshell terminal apply`. The doctor's `iterm2 prefs` row warns until the default profile is nekoshell's.

## Panel

The second profile is a hotkey window: ⌥M, from any application, slides it in docked to the right edge of the screen (iTerm2's window type 6, "Right of screen"), floating and hiding again when it loses focus. It runs `bin/nekoshell music --here` from the checkout with `NEKOSHELL_PANEL=1`, so the greeting stays out of it. `nekoshell music` from a shell inside iTerm2 prints the key and runs the player in the current window; inside tmux it opens a popup. `NEKOSHELL_PANEL_WINDOW_TYPE` in the environment of an apply picks another window type when the docking does not suit the screen.

## Images

iTerm2 draws its own inline image protocol, so the greet plugin passes `--iterm` to fastfetch and the art pack is drawn as a picture. `nekoshell terminal background PATH [OPACITY]` writes the picture into both profiles (`Background Image Location`, with iTerm2's `Blend` set to one minus the opacity; 0.85 by default) and sends the OSC 1337 escape so the window it ran in changes at once; iTerm2 asks for confirmation the first time a program sets a background this way. `none` takes it out of the profiles and clears the current window. The path is stored in `nekoshell.toml` as `background` and `background_opacity` and written again on every theme switch.

## Uninstall

`nekoshell terminal remove iterm2` and `nekoshell uninstall` delete the dynamic profile file, and iTerm2 drops both profiles as soon as it goes. The global preferences cannot be taken back while iTerm2 runs, so the one line that matters is printed instead: with iTerm2 quit, run `defaults delete com.googlecode.iterm2 'Default Bookmark Guid'`. The tab bar, margin, scrollbar and dimming preferences are left as they are.

## Known limits

The global preferences only land with iTerm2 quit, and the shell integration needs the network once. The status bar's directory and git components stay blank until the integration file is sourced by a new shell. The panel's docking depends on the window type and was not confirmed on every screen layout; change `NEKOSHELL_PANEL_WINDOW_TYPE` and apply again if it does not dock to the right. Windows open before an apply keep their old status bar until they are reopened.
